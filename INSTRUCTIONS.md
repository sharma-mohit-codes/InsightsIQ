# Coding Rules

Always read this file before making changes.

Never change architecture unless instructed.

Never rename folders.

Prefer reusable components.

Never duplicate logic.

Keep components under 250 lines.

Prefer readability.

Keep backend modular.

Never install unnecessary libraries.

Whenever implementing a feature:

1. Update TASKS.md

2. Update README if needed.

Never remove comments written by developer.

Only modify files necessary for requested task.

Do not implement future milestones.

Implement exactly what is requested.

If unsure,

ask instead of assuming.


Before implementing any task:

1. Read PROJECT_SPEC.md
2. Read DECISIONS.md
3. Read TASKS.md
4. Follow existing architecture.

Never implement more than one milestone at a time.

After completing a milestone:

- Update TASKS.md
- Suggest a concise git commit message.
- Summarize all files created or modified.

Never continue to another milestone unless explicitly instructed.
